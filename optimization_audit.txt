SSF OPTIMIZATION AUDIT: CODE SPACE, RAM AND PERFORMANCE
=======================================================
Audit date : 2026-11-24
Scope      : the production modules changed in the 48 hours to commit da0a07e (branch mqtt):
             ssftlsc, ssfx509, ssfbn, ssfmqttc, ssfmqttpkt, ssfnetsock, ssfcms, ssfpem,
             ssfpkey, ssfsm, ssfdtime, ssfiso8601 (with their headers and _opt files).
             Unit tests, tools and docs are out of scope; ssftls_certs.c was deleted.
Status     : audit only. Nothing here has been implemented; every item is OPEN.

HOW TO READ THIS FILE
---------------------
Labels      <MODULE>-<nn>, numbered within the module from largest potential to smallest.
            SAFE-<nn> are correctness / safety issues found during the audit (not savings);
            they come first.
            Labels are permanent: when an item is done or rejected, change its Status line
            rather than renumbering.
Categories  CODE (flash: text + rodata), STACK (a function's frame or a call chain's peak),
            STATIC (bss / data), STRUCT (a context or session struct the application
            allocates), HEAP, PERF (time or power).
Estimates   M = measured (a modified copy compiled with the flags below); E = estimated.
            V = also re-checked by the main session (independent rebuild or test run).
            Deltas are per item against the module baseline and are not always additive.
Status      OPEN | DONE <commit> | REJECTED <reason>.

Measurement
  Cortex-M4: arm-none-eabi-gcc -mcpu=cortex-m4 -mthumb -Os -ffunction-sections
  -fdata-sections, SSF_TLS_CONFIG_ENABLE_TRACE=0, unit tests off,
  SSF_CONFIG_ENABLE_THREAD_SUPPORT=0. Stack from -fstack-usage. ssfnetsock uses POSIX
  sockets, so it is measured with host gcc -Os (x86-64; relative only).

  Note: the first measurement pass silently left unit tests on, because ssfassert.h and
  ssfoptions.h include ssfport.h by quoted include. That inflated ssftlsc (16,074 B),
  ssfbn (17,650 B) and ssfpem (739 B). The baselines below are the corrected ones (with
  ssfassert.h and ssfoptions.h shadowed too). Any future measurement must shadow all three.

  Prototypes: the auditors' modified copies are in the session scratch area
  (OPT/<group>/); a reboot may clear them. Each item is described fully enough here to
  redo without them.

SAFETY / CORRECTNESS ISSUES FOUND DURING THE AUDIT (not savings; fix independently)
=====================================================================================

SAFE-01  ssfnetsock: fd_set overflow for a descriptor >= FD_SETSIZE                [V]
  Location : _net/ssfnetsock.c:537 (lookup path), :907-908 (pollOpen)
  Issue    : FD_SET(fd, ...) on a stack fd_set with no FD_SETSIZE bound anywhere. On a
             glibc host a process with >= 1024 open descriptors writes past the fd_set
             (or aborts under _FORTIFY_SOURCE). Embedded stacks (lwIP) use small fds.
  Fix      : use poll() on POSIX (also NETSOCK-01), or check fd < FD_SETSIZE and fail.
  Status   : OPEN

SAFE-02  ssfbase64 (used by ssfpem / ssfpkey): data-dependent timing over key text    [V]
  Location : _codec/ssfbase64.c:46-57 (_SSFBase64GetEncoding), called per quad from
             _codec/ssfpem.c:166
  Issue    : each Base64 character is decoded by a linear search of the 65-character
             alphabet, so decode time depends on the character: a known side channel for
             PEM private keys. ssfbase64 was not changed in the window; it is listed
             because ssfpem / ssfpkey route private keys through it.
  Fix      : branch-free range decode (A-Z, a-z, 0-9, +, /, = by masks). Measured: +94 B
             code, 3.4x faster on the host (~150 -> ~40 cycles/char on M4, E); checked
             against the old table for all 256 byte values. Also PEM-01.
  Status   : OPEN

SAFE-03  ssfbn: a window size that does not divide 32 silently gives wrong results     [V]
  Location : _opt/ssfbn_opt.h:52-59 (SSF_BN_MODEXP_WIN_K), _crypto/ssfbn.c:2945
  Issue    : nWindows = bits / k truncates for k not dividing 32. The option's comment
             warns of this, but nothing enforces it: -DSSF_BN_MODEXP_WIN_K=3 builds an
             RSA / EC library that computes wrong answers (the BN unit test fails at
             ssfbn_ut.c:2561 with k=3, M).
  Fix      : nWindows = (bits + k - 1) / k (loop count still exponent-independent;
             SSFBNGetBit returns 0 past e->len), which also makes k=3 a valid stack choice
             (BN-03); or at least an #error for non-divisors.
  Status   : OPEN

SAFE-04  ssfx509: SSF_X509_CONFIG_MAX_CHAIN_DEPTH cannot be overridden with -D
  Location : _opt/ssfx509_opt.h:21 (no #ifndef guard)
  Issue    : config hygiene, not a bug: the option cannot be set from the build line,
             unlike the other SSF options.
  Fix      : wrap it in #ifndef.
  Status   : OPEN

TLSC-01  STRUCT  -16,384 B per session (43,264 -> 26,824 with H)                  M V
  Location : _net/ssftlsc.h:343-349; _net/ssftlsc.c:282-492, 540, 3645
  What     : recvBuf (16,406 B, ciphertext) and hsBuf (16,385 B, plaintext) are two
             full-size copies of each record; all three AEADs decrypt exactly in place
             (GCM / CCM authenticate before writing).
  Change   : read the 5-byte header into ioCtx.hdr[5] and the fragment straight to
             &hsBuf[hsBufLen]; decrypt in place there (the AAD header placed in 5 bytes of
             headroom just before the fragment and restored, or a separate-header decrypt
             in ssftls); plaintext records need no memcpy. hsBuf +16 B for the tag; the
             message cap stays MAX_RECV+1. Saves about MAX_RECV_RECORD+1 at any receive size.
  Risk     : medium. Header checks, alerts, constant-time AEAD and wiping are unchanged
             (one buffer to wipe instead of two). Invariant: a record may be part-received
             only while hsBufPos == 0, so compaction never strands fragment bytes.
             Prototype H also dropped the "ServerHello: suite / group" trace when it merged
             the two ServerHello paths (TLSC-03): keep that trace.
  Status   : DONE (2026-11-24): design 1B (SSFTLSRecordDecrypt takes the header
             and fragment apart), separate plaintext / protected fit checks at the header,
             an assert that the fragment's destination never moves mid-record. Measured
             (M4, unit tests off): session 43,264 -> 26,888 B (-16,376 B); ssftlsc code
             +10 B (13,615 B; the audit's fixes: a distinct trace for a plaintext record
             over 2^14, and protected handshake messages capped one byte lower, refused at
             their header); ssftls code +40 B (the pt / frag / hdr overlap rules).
