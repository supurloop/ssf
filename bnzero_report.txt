SSF BIGNUM STORAGE ZERO-FILL REMOVAL: BEFORE / AFTER
====================================================
Date       : 2026-11-26
Scope      : codesize_audit.txt item #6. SSFBN_DEFINE, SSFBNMONT_DEFINE (ssfbn.h) and
             SSFECPOINT_DEFINE (ssfec.h) no longer zero their limb storage. Before = commit
             da0b8c8 (branch mqtt); after = that commit plus this change.
Status     : implemented.

SUMMARY
-------
  Code space   client image -2,272 B (M4) / -2,452 B (M0+); all objects -3,332 / -3,692 B
  Performance  ECC 1.4-3.6% fewer instructions; RSA unchanged (<0.1%)
  Stack        ECC entry points 112-128 B less; RSA within +-32 B (worst: +8 B on ARM,
               +32 B host RSA-2048 keygen)
  RAM          no change to static RAM (data/bss)

THE CHANGE
----------
  - The three macros declare storage without "= {0u}". len still starts at 0.
  - Unit-test builds (SSF_CONFIG_UNIT_TEST == 1) fill the storage with SSF_BN_UT_UNINIT_FILL
    (0xA5A5A5A5) through _SSFBNUTFill(), so any code that relies on zeroed limbs fails its tests.
    Production builds get no extra code.
  - New tests at the top of SSFBNUnitTest and SSFECUnitTest check that freshly declared storage
    holds the fill pattern (red before the change: SSF_BN_UT_UNINIT_FILL undefined).
  - ssfbn.md and ssfec.md now say the storage is uninitialized and every limb below len must be
    written before it is read.

VERIFICATION
------------
  - Full suite in a scratch tree with fill 0xA5A5A5A5, with fill 0xFFFFFFFF, and with no fill
    at all: 62/62 passed each time. ASan suite with 0xA5A5A5A5: 62/62, no reports.
  - In the repo after the change: ssfbn, ssfec, ssfecdsa, ssfrsa, ssfx509, ssfcms, ssfpkey,
    ssftls and ssftlsc unit tests pass. Host build: 0 warnings. build-arm.sh: 0 warnings (the
    3 POSIX-only files fail to compile, as before).
  - Residual risk: tests only cover the paths they exercise. No SSF code relied on zeroed
    storage, consistent with the existing rule that callers zero-pad shorter inputs.

under qemu-arm 10.0 in the ssf-cross image with -d in_asm,exec,nochain; instructions = sum over
translation blocks of (block size x executions). One operation per run; program start-up and
any setup (deriving a public key, making the signature to verify) are measured separately and
subtracted. Thumb-2 on ARMv7-A is a close proxy for Cortex-M4. Entropy is a fixed xorshift
